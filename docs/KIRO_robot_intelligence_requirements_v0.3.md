# KIRO 로봇 인텔리전스 플랫폼 요구사항 정의서

- 문서 버전: v0.3
- 작성일: 2026-08-04
- 대상 단계: 완전 무료 프로토타입 / Phase 1 MVP
- 서비스 범위: 한국로봇융합연구원 내부 직원 전용
- AI 전제: Gemini API 무료 티어
- 검색 전제: 한국어 부분 문자열 일치 지원
- 운영 전제: 전담 분석가 없음, 운영 책임자 월 1~2시간 이내
- 문서 상태: 개발 착수용 요구사항 초안

---

## 1. 문서 목적

본 문서는 공개된 국내외 로봇 정책·산업·기술 정보를 자동으로 수집하고, Gemini API 무료 티어를 활용해 분류·요약·분석한 뒤 KIRO 직원에게 제공하는 내부 웹사이트의 Phase 1 MVP 요구사항을 정의한다.

본 버전은 장기 제품 비전 전체가 아니라, 실제로 완성하고 사용할 수 있는 첫 번째 프로토타입 범위만 정의한다.

구체적인 기술 스택, 배포 방식, 데이터베이스, 크롤링 프레임워크, Gemini 모델 선택 및 프롬프트 구조는 후속 `design.md`에서 정의한다.

---

## 2. 제품 정의

### 2.1 한 문장 정의

> 공개된 로봇 정책·산업·기술 정보를 AI가 자동으로 수집·선별·분석하여, 준실시간 동향과 KIRO 연구원 관점의 시사점, 격주 브리프 및 검색 가능한 과거 자료를 제공하는 내부 로봇 인텔리전스 웹사이트.

### 2.2 해결하려는 문제

- 직원이 다수의 뉴스, 정부 발표, 기업 발표를 직접 찾아 읽어야 한다.
- 동일한 사건이 여러 언론에 반복 보도되어 중요한 정보처럼 과대 노출된다.
- 정책·산업·기술 정보가 흩어져 있어 기간별 흐름 파악이 어렵다.
- 상시 분석 담당자가 없어 정기적인 브리프 작성과 사이트 운영이 어렵다.
- 과거 보고서가 문서 단위로 보관되어 검색과 재활용이 불편하다.
- 단순 요약만으로는 KIRO 업무와의 관련성을 파악하기 어렵다.

### 2.3 핵심 가치

본 시스템의 목적은 뉴스를 많이 보여주는 것이 아니다.

> 직원이 짧은 시간 안에 무엇이 새로 나왔는지, 핵심 사실이 무엇인지, KIRO가 왜 주목해야 하는지 파악하도록 돕는 것이 핵심 가치이다.

## 3. 확정된 운영 전제

### 3.1 사용자와 접근 범위

- 1차 서비스는 KIRO 내부 직원 전용이다.
- 모든 KIRO 직원은 전체 동향, 분석, KIRO 시사점 및 브리프를 열람할 수 있다.
- 부서별 열람 제한은 Phase 1에서 적용하지 않는다.
- 외부 공개 사이트와 외부 사용자는 Phase 1 범위에 포함하지 않는다.

### 3.2 운영 인력

> 전담 분석가는 두지 않는다. 시스템 운영 책임자 1인을 명목상 지정하며, 정상 운영 시 정기 관리 업무는 월 1~2시간 이내를 목표로 한다.

운영 책임자의 기본 업무는 다음으로 제한한다.

- 월 1회 수집·분석 상태 확인
- 장기간 실패한 수집원 확인
- 직원이 신고한 명백한 오류 확인
- 격주 브리프 정상 발행 여부 확인
- Gemini 무료 티어 한도 초과 및 처리 지연 확인

정상 콘텐츠를 사람이 사전 승인하는 절차는 두지 않는다.

### 3.3 AI 서비스와 비용

- MVP는 Gemini API 무료 티어에서 운영한다.
- 유료 API, 자체 GPU, 로컬 LLM은 Phase 1 범위에서 제외한다.
- 특정 Gemini 모델명이나 무료 한도 수치는 고정 요구사항으로 두지 않는다.
- 모델과 무료 티어 한도는 변경될 수 있으므로 설정값으로 관리한다.
- 공개된 외부 자료만 Gemini API에 입력한다.
- 공개자료를 바탕으로 한 KIRO 연구원 차원의 시사점 생성은 허용한다.
- 내부 회의자료, 미공개 사업계획, 개인정보, 계약·평가·보안자료는 입력하지 않는다.

### 3.4 브리프 주기

- 정기 발행 기본 주기는 격주이다.
- 기준일과 발행 시각은 설정할 수 있어야 한다.
- 주간 또는 월간으로의 변경은 향후 운영 결과에 따라 결정한다.

## 4. Phase 1 목표

Phase 1에서는 다음 흐름을 완성한다.

```text
수집
→ 로봇 관련성 필터
→ 단순 중복 클러스터링
→ 축소 분류
→ 사실·AI 해석·KIRO 시사점 생성
→ 동향 피드 자동 게시
→ 검색·아카이브
→ 격주 브리프 자동 생성·발행
```

### 4.1 Phase 1 성공 상태

- 직원이 로그인 후 최신 로봇 동향을 확인할 수 있다.
- 동일하거나 매우 유사한 기사가 반복 노출되지 않는다.
- 각 동향에서 확인된 사실, AI 해석, KIRO 시사점이 분리되어 보인다.
- 원문 링크를 확인할 수 있다.
- 정책·산업·기술 및 주요 지역·로봇 분야로 필터링할 수 있다.
- 과거 동향과 격주 브리프를 검색·열람할 수 있다.
- 사람의 사전 승인 없이 동향과 브리프가 자동 게시된다.
- 운영 책임자의 정상 관리 시간이 월 1~2시간을 넘지 않는다.
- 시스템이 무료 Gemini API 한도 초과 시 작업을 연기하고 자동 복구한다.

---

## 5. Phase 1 비목표

다음 항목은 Phase 1에서 구현하지 않는다.

- 영속적인 핵심 이슈 자동 생성 및 상태 관리
- 사건을 장기간 자동 연결하는 타임라인
- 공식자료와 재인용 기사 간 정보 계보 추적
- 출처 간 의미적 수치 충돌 자동 판정
- 원 논문·연구기관 자료 자동 추적
- 정교한 출처 다양성·편향 점수
- 모든 필드에 대한 전체 버전 비교
- 복잡한 사건 수동 병합·분리 UI
- 세부 태그 병합 및 온톨로지 관리
- 자연어 대화형 검색
- 개인별 추천 피드
- SNS 전체 수집
- 논문·특허 데이터베이스 전수 수집
- 외부 공개 사이트
- 자동 사업기획서 완성본 생성
- 네이티브 모바일 앱

이 항목들은 Phase 2 이후 백로그로 관리한다.

# 8. 기능 요구사항

## FR-001 내부 접근

### 요구사항

시스템은 인증된 KIRO 내부 사용자만 접근할 수 있어야 한다.

### 수용 기준

- **WHEN** 인증되지 않은 사용자가 내부 URL에 접근하면  
  **THEN** 시스템은 로그인 화면 또는 접근 거부 화면을 표시해야 한다.
- **WHEN** 일반 직원이 로그인하면  
  **THEN** 모든 동향, 브리프 및 KIRO 시사점을 열람할 수 있어야 한다.
- **WHEN** 일반 직원이 운영 메뉴 URL에 직접 접근하면  
  **THEN** 시스템은 접근을 거부해야 한다.

---

## FR-002 수집원 관리

### 요구사항

시스템은 특정 사이트에 종속되지 않는 수집원 목록을 관리해야 한다.

Phase 1에서 지원하는 수집 방식:

- RSS·Atom
- 공개 목록 페이지
- 수동 URL 등록
- 구현 난도가 낮은 사전 정의 수집기

관리 항목:

```text
수집원 이름
출처 유형
국가·권역
언어
수집 URL
수집 방식
수집 주기
활성 상태
마지막 성공 시각
마지막 실패 시각
오류 메시지
```

출처 유형:

- 정부·공공기관
- 기업 공식 발표
- 연구기관·대학
- 전문 기술 큐레이션 매체
- 로봇·산업 전문매체
- 일반 언론
- 정책·사업 공고

IEEE Spectrum Robotics는 전문 기술 큐레이션 출처의 초기 예시일 뿐, 시스템의 필수 기능이나 전용 처리 대상으로 취급하지 않는다.

### 수용 기준

- **WHEN** 운영 책임자가 등록된 수집원을 비활성화하면  
  **THEN** 다음 수집 주기부터 해당 수집원에서 신규 자료를 가져오지 않아야 한다.
- **WHEN** 한 수집원에서 오류가 발생하면  
  **THEN** 다른 수집원의 수집 작업은 계속 실행되어야 한다.
- **WHEN** 표준 RSS 주소가 등록되면  
  **THEN** 코드 수정 없이 신규 항목을 수집할 수 있어야 한다.
- 임의의 모든 웹사이트를 코드 수정 없이 수집하는 기능은 Phase 1 완료 조건이 아니다.

## FR-003 자동 수집과 신선도

### 요구사항

- 활성 수집원은 설정된 주기에 따라 자동 확인한다.
- 기본 수집 확인 주기는 최대 3시간으로 한다.
- 수집된 자료는 중복 처리와 AI 분석이 완료된 후 자동 게시한다.
- 정상 처리된 자료는 수집 후 60분 이내 노출을 목표로 한다.
- 마지막 정상 갱신 시각을 화면에 표시한다.

### 수용 기준

- **WHEN** 수집원에 새로운 항목이 게시되고 다음 수집 주기가 실행되면  
  **THEN** 시스템은 신규 URL과 기본 메타데이터를 저장해야 한다.
- **WHEN** 신규 자료가 정상적으로 분석되면  
  **THEN** 수집 완료 후 60분 이내 최신 동향에 표시해야 한다.
- **WHEN** 수집 또는 분석이 실패하면  
  **THEN** 시스템은 실패 상태를 기록하고 다음 주기에서 자동 재시도해야 한다.
- **WHEN** 전체 갱신이 지연되면  
  **THEN** 홈과 운영 화면에 마지막 정상 갱신 시각을 표시해야 한다.

---

## FR-004 관련성 필터

### 요구사항

AI 또는 경량 규칙은 수집된 콘텐츠가 로봇 정책·산업·기술과 실질적으로 관련되는지 판별해야 한다.

제외 대상 예시:

- 로봇이 부수적으로만 언급된 콘텐츠
- 광고·협찬 중심 콘텐츠
- 단순 행사 안내
- 정보가 거의 없는 홍보성 영상
- 동일 보도자료를 제목만 바꾼 콘텐츠
- 근거가 없는 과장성 전망
- KIRO 업무와 관련성이 매우 낮은 흥미성 콘텐츠

### 수용 기준

- **WHEN** 콘텐츠가 로봇과 직접 관련이 없다고 판정되면  
  **THEN** 최신 동향 목록에 노출하지 않아야 한다.
- **WHEN** 판정이 불확실하면  
  **THEN** 콘텐츠를 자동 폐기하지 않고 낮은 우선순위 상태로 보관할 수 있어야 한다.
- **WHEN** 운영 책임자가 제외 항목을 재분석하면  
  **THEN** 새 분석 결과로 노출 여부를 다시 결정해야 한다.

---

## FR-005 단순 중복 클러스터링

### 요구사항

동일하거나 매우 유사한 사건을 다룬 콘텐츠는 하나의 동향 카드로 묶어야 한다.

Phase 1 판단 기준:

- 동일 URL
- 제목 유사도
- 본문 유사도
- 발표기관 또는 기업
- 발표일
- 정책명·제품명·사업명

Phase 1에서는 정보 계보와 독립 취재 여부까지 판정하지 않는다.

### 수용 기준

- **WHEN** 동일 URL이 다시 수집되면  
  **THEN** 별도 콘텐츠로 중복 저장하지 않아야 한다.
- **WHEN** 제목·본문·기관·날짜가 매우 유사한 콘텐츠가 여러 건 존재하면  
  **THEN** 하나의 대표 동향과 관련 출처 목록으로 표시해야 한다.
- **WHEN** 공식 발표와 일반 기사가 같은 클러스터에 있으면  
  **THEN** 가능한 경우 공식 발표를 대표 출처로 우선 표시해야 한다.
- 잘못 묶인 콘텐츠를 세밀하게 분리하는 관리 UI는 Phase 1 완료 조건이 아니다.

## FR-007 AI 구조화 분석

### 요구사항

관련성과 중복 처리가 끝난 대표 콘텐츠는 가능한 한 한 번의 Gemini 호출로 다음 결과를 구조화해 생성해야 한다.

```text
제목
한 문장 요약
확인된 핵심 사실 2~5개
핵심 수치·일정
분야
지역
로봇 분야
기관·기업·정책·기술 키워드
AI가 판단한 의미
KIRO 시사점
근거 수준
```

### 표시 구분

1. **확인된 사실**
2. **AI 해석**
3. **KIRO 시사점**
4. **확인 필요 또는 한계**

### 간소화된 평가

- 근거 수준: 강함 / 보통 / 약함
- KIRO 관련성: 직접 / 간접 / 낮음
- 중요도: 높음 / 보통 / 낮음

숫자형 100점 점수는 Phase 1에서 사용하지 않는다.

### 수용 기준

- **WHEN** 분석 결과가 게시되면  
  **THEN** 확인된 사실, AI 해석, KIRO 시사점이 서로 다른 영역에 표시되어야 한다.
- **WHEN** 원문에서 수치 또는 날짜가 확인되지 않으면  
  **THEN** AI는 임의의 값을 생성하지 않고 `확인되지 않음`으로 표시해야 한다.
- **WHEN** 기업 공식 발표의 성능 주장을 요약하면  
  **THEN** `기업 발표 기준`임을 표시해야 한다.
- **WHEN** AI 분석 구조가 유효한 JSON 형식으로 반환되지 않으면  
  **THEN** 시스템은 자동 재시도하고, 계속 실패하면 원문 메타데이터만 보관해야 한다.

## FR-011 통합검색

### 요구사항

키워드 및 필터 기반 검색을 제공해야 한다.

- 시스템은 한국어 단어에 조사·어미·접사가 붙어 있어도 핵심 부분 문자열로 검색할 수 있어야 한다.
- 1글자 검색은 과도한 결과와 성능 저하를 막기 위해 제한하거나 정확 일치 방식으로 처리할 수 있다.
- 2글자 이상의 검색어는 부분 문자열 일치를 지원해야 한다.

검색 대상:

- 제목
- 한 문장 요약
- 확인된 사실
- KIRO 시사점
- 기관·기업
- 정책명·사업명
- 기술명
- 추출 키워드
- 격주 브리프 본문

### 수용 기준

- **WHEN** 사용자가 검색어를 입력하면  
  **THEN** 제목과 본문 분석 결과에서 일치하는 동향과 브리프를 표시해야 한다.
- **WHEN** 사용자가 `휴머노이드`를 검색하고 저장된 콘텐츠에 `휴머노이드가`, `휴머노이드를`, `휴머노이드용`이 포함되어 있으면  
  **THEN** 시스템은 해당 콘텐츠를 검색 결과에 표시해야 한다.
- **WHEN** 검색어와 필터를 함께 사용하면  
  **THEN** 두 조건을 모두 만족하는 결과를 표시해야 한다.
- **WHEN** 사용자가 1글자 검색어를 입력하면  
  **THEN** 시스템은 검색을 제한하거나 정확 일치 방식으로 처리할 수 있어야 한다.
- 자연어 질문에 답변을 생성하는 기능은 Phase 1 완료 조건이 아니다.

## FR-012 격주 브리프 자동 생성

### 요구사항

시스템은 2주간 게시된 동향 중 중요도와 근거 수준이 높은 항목을 중심으로 격주 브리프를 자동 생성해야 한다.

### 브리프 기본 구조

기존 KIRO 보고서의 익숙한 골격을 유지한다.

```text
1. 한 페이지 요약
   - 이번 기간 핵심 변화 3~5개
   - 종합 시사점

2. 정책 동향
   - 국내
   - 미국
   - 중국
   - 일본
   - 유럽·기타

3. 산업 동향
   - 해외
   - 국내

4. 기술 동향

5. 이전 기간 대비 달라진 점

6. KIRO 시사점

7. 향후 2주 추적 항목

8. 근거자료
```

### 발행 정책

- 사람의 사전 승인을 요구하지 않는다.
- 일부 저신뢰 항목이 있어도 브리프 전체를 조용히 보류하지 않는다.
- 근거가 약한 항목은 경고 표시 또는 제외 후 나머지 내용으로 발행한다.
- 브리프 생성 자체가 실패하면 운영 책임자에게 명확한 실패 상태를 표시한다.

### 수용 기준

- **WHEN** 설정된 격주 발행 시각이 되면  
  **THEN** 시스템은 해당 기간의 분석 완료 동향으로 브리프를 생성해야 한다.
- **WHEN** 근거가 약한 항목이 포함되면  
  **THEN** 해당 항목에 경고를 표시하거나 제외하고 브리프를 발행해야 한다.
- **WHEN** 브리프가 발행되면  
  **THEN** 사용된 동향 목록과 생성 시각을 저장해야 한다.
- **WHEN** 브리프를 재생성하면  
  **THEN** 기존 발행본을 덮어쓰지 않고 새 버전으로 저장해야 한다.
- 영속적인 핵심 이슈 데이터베이스와 자동 타임라인은 브리프 생성의 필수 조건이 아니다.

- 확인 완료
- 콘텐츠 숨김
- AI 재분석
- 신고 기각

## FR-015 운영 현황과 무료 티어 한도 대응

### 요구사항

운영 화면은 최소 다음 현황을 표시해야 한다.

```text
오늘 수집 건수
오늘 게시 건수
관련성 제외 건수
중복 클러스터 수
AI 분석 성공·실패 건수
마지막 정상 수집 시각
수집원별 마지막 성공·실패
Gemini 호출 수
429 또는 한도 초과 횟수
대기 중인 분석 작업 수
최근 브리프 발행 상태
```

### 한도 초과 처리

- 무료 한도를 초과하면 작업을 삭제하지 않는다.
- 낮은 우선순위 동향 분석은 다음 처리 주기로 연기한다.
- 브리프 생성 작업은 일반 동향 처리보다 높은 우선순위를 가진다.
- 재시도는 지수 백오프 또는 다음 예약 주기를 사용한다.

### 수용 기준

- **WHEN** Gemini API가 한도 초과 응답을 반환하면  
  **THEN** 작업을 대기 상태로 저장하고 자동 재시도해야 한다.
- **WHEN** 대기 작업이 존재하면  
  **THEN** 운영 화면에 대기 건수와 가장 오래된 대기 시간을 표시해야 한다.
- **WHEN** 브리프 생성일에 무료 한도가 부족하면  
  **THEN** 일반 동향 분석보다 브리프 생성 작업을 우선 처리해야 한다.
- **WHEN** 한 달 동안 오류 신고와 장기 장애가 없으면  
  **THEN** 운영 책임자가 콘텐츠를 개별 검토하지 않고도 시스템이 정상 운영되어야 한다.

# 9. AI 처리 원칙

## AIR-001 단일 구조화 호출 우선

관련성 필터와 중복 클러스터링 이후의 대표 콘텐츠에 대해, 분류·요약·사실 추출·KIRO 시사점 생성을 가능한 한 하나의 구조화된 호출로 수행한다.

필요 이상의 다단계 LLM 호출은 피한다.

## AIR-002 근거 기반 생성

- 원문에서 확인되지 않은 구체적인 날짜, 수치, 기관명을 생성하지 않는다.
- AI 해석과 KIRO 시사점은 확인된 사실과 별도 영역에 둔다.
- 불확실한 내용은 단정하지 않는다.

## AIR-003 공개자료 입력 원칙

입력 가능:

- 공개 정부·공공기관 자료
- 공개 기업 발표
- 공개 연구기관·대학 자료
- 공개 뉴스·전문매체 기사
- 공개자료만을 바탕으로 생성된 일반적인 KIRO 시사점

입력 금지:

- 내부 회의자료
- 미공개 사업·과제 기획
- 개인정보
- 계약·평가·보안자료
- 직원의 비공개 메모

## AIR-004 모델 교체 가능성

- 모델명은 설정값으로 관리한다.
- Gemini 무료 티어에서 사용 가능한 모델 변경에 대응할 수 있어야 한다.
- 모델 변경 후에도 기존 콘텐츠와 브리프를 열람할 수 있어야 한다.

## AIR-005 실패 허용

- AI 분석 실패가 전체 수집 작업을 중단시켜서는 안 된다.
- 분석에 실패한 콘텐츠는 재시도 대기 또는 메타데이터 전용 상태로 보존한다.
- 일부 콘텐츠 실패 때문에 브리프 전체가 무기한 발행되지 않아서는 안 된다.

# 10. 비기능 요구사항

## NFR-001 성능

초기 목표:

- 일반 페이지: 3초 이내
- 검색·필터 결과: 3초 이내
- 상세 페이지: 3초 이내
- 운영 현황: 5초 이내

이는 개발 완료 후 내부 환경에서 검증하며, 데이터 규모에 따라 조정할 수 있다.

## NFR-002 신선도

- 기본 수집 확인 주기: 최대 3시간
- 정상 분석된 콘텐츠 노출: 수집 후 60분 이내 목표
- 마지막 정상 갱신 시각 표시
- 실패 작업 자동 재시도

## NFR-003 가용성

- 한 수집원 장애가 다른 수집원과 사용자 열람 기능에 영향을 주지 않아야 한다.
- Gemini API 한도 초과 중에도 기존 콘텐츠 열람과 검색은 가능해야 한다.
- 배치 작업과 사용자 화면은 가능한 한 분리되어야 한다.

## NFR-004 보안

- 내부 인증 없이 콘텐츠를 열람할 수 없어야 한다.
- 관리자 기능은 운영 책임자에게만 제공한다.
- API 키를 프론트엔드 코드나 브라우저에 노출하지 않는다.
- 외부 원문의 스크립트와 HTML을 그대로 실행하지 않는다.

## NFR-005 저작권

- 외부 기사 본문 전체를 무단 복제하지 않는다.
- 제목, URL, 발행일, 출처, 분석에 필요한 최소 텍스트 및 독자적인 AI 요약을 저장한다.
- 원문으로 이동할 수 있는 링크를 제공한다.
- 외부 이미지는 사용 권한이 확인되지 않으면 복제하지 않는다.

## NFR-006 운영성

- 정상 운영 시 사람의 사전 콘텐츠 검토를 요구하지 않는다.
- 운영 책임자가 월 1회 한 화면에서 장애·신고·브리프·Gemini 한도 상태를 확인할 수 있어야 한다.
- 소스별 파서 수정처럼 개발이 필요한 작업은 월 1~2시간 운영 목표에 포함하지 않으며 유지보수 작업으로 별도 구분한다.

# 13. 측정 가능한 성공 기준

파일럿 운영 1개월 후 다음을 확인한다.

### 필수 기준

- 격주 브리프가 사람의 사전 승인 없이 정해진 일정에 발행된다.
- 정상 수집원에서 가져온 신규 콘텐츠가 목표 시간 내 최신 동향에 노출된다.
- 동일 URL이 중복 카드로 노출되지 않는다.
- 모든 상세 페이지에 원문 링크가 존재한다.
- 모든 상세 페이지에서 사실·AI 해석·KIRO 시사점이 구분된다.
- 한국어 단어에 조사·어미가 붙은 콘텐츠도 핵심 검색어로 조회된다.
- Gemini 한도 초과 시 작업이 유실되지 않고 재처리된다.
- 운영 책임자의 실제 관리 시간이 월 1~2시간 이내이다.

- 월간 수집 건수

- 중복 클러스터 비율

# 14. 완료 정의

Phase 1 MVP는 다음 조건을 모두 만족할 때 완료된 것으로 본다.

1. KIRO 직원이 로그인 후 최신 정책·산업·기술 동향을 열람할 수 있다.
2. 시스템이 등록된 수집원에서 3시간 이내 주기로 신규 자료를 확인한다.
3. 동일 URL과 매우 유사한 기사가 중복 카드로 반복 노출되지 않는다.
4. 각 동향에서 확인된 사실, AI 해석, KIRO 시사점이 구분된다.
5. 각 동향에서 대표 원문과 관련 출처 링크를 확인할 수 있다.
6. 분야·지역·로봇 분야 필터와 키워드 검색을 사용할 수 있다.
7. 정책·R&D 정보를 별도로 탐색할 수 있다.
8. 기존 KIRO 보고서 골격을 유지한 격주 브리프가 자동 생성·발행된다.
9. 발행된 브리프는 당시 상태로 보존된다.
10. 연도·월·격주 기준으로 과거 동향과 브리프를 탐색할 수 있다.
11. 오류 신고, 콘텐츠 숨김 및 재분석이 가능하다.
12. Gemini 무료 티어 한도 초과 시 작업이 유실되지 않고 자동 재시도된다.
13. 정상 운영에 상시 분석 담당자나 사전 승인자가 필요하지 않다.
14. 파일럿 1개월 동안 운영 책임자의 정기 관리 시간이 월 1~2시간 이내이다.
