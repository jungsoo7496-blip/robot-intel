# 0. 작업 수행 규칙

## 0.1 기본 원칙

검증 시점 표기:

- **즉시 검증**: 해당 태스크 안에서 바로 확인한다.
- **Gate B 지연 검증**: 자동 처리 파이프라인이 완성된 뒤 확인한다.
- **Gate C E2E 검증**: 사용자 화면과 전체 기능이 연결된 뒤 확인한다.

- [ ] 한 번에 하나의 상위 작업만 구현한다.
- [ ] 각 상위 작업은 별도 브랜치 또는 명확한 커밋 단위로 관리한다.
- [ ] 작업 완료 전 관련 단위 테스트와 통합 테스트를 실행한다.
- [ ] 환경변수, API 키, Supabase 서비스 역할 키를 저장소에 커밋하지 않는다.
- [ ] 데이터베이스 변경은 반드시 마이그레이션 파일로 관리한다.
- [ ] 프롬프트 변경은 파일 버전과 `prompt_version`을 함께 변경한다.
- [ ] Phase 2 항목은 구현하지 않고 백로그로만 남긴다.
- [ ] 구현 중 설계 변경이 필요하면 먼저 `design.md`에 결정 근거를 기록한다.

## 0.2 Phase 1에서 구현하지 않을 항목

- 핵심 이슈 자동 생성 및 장기 상태 관리
- 사건 장기 타임라인
- 정보 계보와 독립 출처 판정
- 출처 간 의미적 수치 충돌 탐지
- 논문·특허 전수 수집
- 벡터 DB와 RAG
- 자연어 대화형 검색
- 개인별 추천
- 외부 공개 사이트
- 다중 무료 LLM 자동 폴백
- 복잡한 다단계 승인
- 네이티브 모바일 앱

- [ ] 등록된 수집원이 최대 3시간 주기로 확인된다.
- [ ] 동일 URL과 유사 기사가 중복 카드로 반복되지 않는다.
- [ ] 사실·AI 해석·KIRO 시사점이 구분된다.
- [ ] 원문과 관련 출처 링크를 확인할 수 있다.

- [ ] 기존 KIRO 골격의 격주 브리프가 자동 발행된다.
