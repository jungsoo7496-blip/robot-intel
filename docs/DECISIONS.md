# 설계 변경 기록

## D-003. Vercel 배포 — 열람 공개 허용, 관리 영역만 보호 (2026-08-07)

### 결정

프론트엔드를 Vercel 무료 티어에 배포하며, **열람은 공개 접근을 허용한다**
(운영자 확인). 근거:

- 사이트의 모든 콘텐츠는 공개자료 기반 AI 요약이며, 기관 내부 정보는
  시스템에 입력되지 않는다 (AIR-003).
- 외부인이 열람해도 실질적 피해가 없다. 보호 대상은 관리 기능뿐이다.

보호 경계:

- `/admin` — 마스터 OPERATOR 로그인 + 서버 측 역할 검사 (D-001 유지)
- Supabase 운영 테이블 — RLS로 익명·USER 차단 (0004·0005·0007)
- 익명이 볼 수 있는 것은 게시된 콘텐츠뿐 (0007로 검증됨)

### 비상 잠금 스위치 (옵션)

`SITE_ACCESS_TOKEN` 환경변수를 설정하면 `?access=<토큰>` 링크를 통한
진입만 허용하는 게이트가 활성화된다. 평상시에는 비워 두고(게이트 꺼짐),
스크래핑 남용 등 문제가 생기면 Vercel 환경변수 설정만으로 잠글 수 있다.

D-001의 "상위 포털 내부로만 노출" 주의사항은 본 결정으로 대체한다.

## D-002. 수집·분석 워크플로 분리 (2026-08-06)

설계 v0.3 §19.1은 "파일럿에서 단일 job으로 시작, 조건 충족 시 분리 검토"였다.
외부 코드 리뷰(P0-2)에서 수집원 확대(구글 뉴스 링크 디코딩 포함) 이후 수집
단계만으로 5분 timeout을 초과해 분석이 실행되지 못하는 기아(starvation)
가능성이 확인되어, 분리 조건 관측을 기다리지 않고 즉시 분리한다.

- `collect.yml`: 6시간 주기, timeout 9분, 내부 soft deadline 420초
- `analyze.yml`: 3시간 주기, timeout 5분 (기존 배치 종료 조건 유지)
- 예상 실사용 시간은 월 1,500분 내부 예산 이내 (수집 4회×실사용 ≤7분
  + 분석 8회×실사용 ≤5분 ≈ 일 60분 상한, 실측은 workflow_usage로 관측)

같은 리뷰에서 반영한 사항: 익명 RLS를 게시 범위로 제한(0007), data-only
백업과 복구 절차(docs/RESTORE.md), Gemini 비정상 응답 시 작업 단위 실패
처리, 수집원 시드 버전 관리(seed_sources.sql), 브리프 부록 스냅샷,
대표 출처 교체 시 재분석, SSRF 방어(net_guard), 로그인 next 경로 제한, CI.

## D-001. 개인 계정 가입 제거, 익명 열람 + 마스터 운영자 계정 (2026-08-05)

### 변경 내용

requirements v0.3의 FR-001(내부 접근)·설계 v0.3 §16(인증)을 다음과 같이 변경한다.

- 기존: 직원 각자 가입(허용 도메인 검사 + 이메일 인증) 후 개인 계정으로 열람
- 변경:
  - 열람 기능(홈·최신 동향·정책·브리프·아카이브·검색)은 **로그인 없이 접근 가능**
  - 관리 기능(`/admin`)은 **마스터 운영자 계정 1개**로만 로그인
  - 자체 가입 기능 제거 (가입 UI 제거, 허용 도메인 목록 비움)

### 근거

- 이 사이트는 **이미 로그인이 필요한 내부 사이트(포털) 안에** 게시될 예정이므로,
  접근 통제는 상위 포털 인증이 담당한다. 개별 재로그인은 불필요한 마찰이다.
- 전담 분석가·계정 관리자가 없는 운영 전제(월 1~2시간)와도 부합한다.

### 영향과 주의사항

- NFR-004의 "내부 인증 없이 열람 불가" 조항은 **상위 포털 인증으로 대체**된 것으로 본다.
- 배포 URL이 포털 밖에서 직접 접근 가능하면 사실상 외부 공개가 되므로,
  **배포 시 포털 내부 경로/프록시를 통해서만 노출되도록 확인해야 한다.**
- Supabase anon 키는 클라이언트 번들에 포함되며, 익명 읽기 정책으로 인해
  키를 아는 사람은 게시 콘텐츠를 REST로 읽을 수 있다. 게시 콘텐츠는 공개자료
  기반 요약이므로 수용 가능한 위험으로 판단한다. 운영 테이블은 계속 차단된다.
- 오류 신고는 익명으로도 제출 가능하도록 `error_reports.reported_by`를 nullable로 변경.
- 개인별 열람 이력·개인화 기능은 불가능해진다 (Phase 1 범위에 없음).
